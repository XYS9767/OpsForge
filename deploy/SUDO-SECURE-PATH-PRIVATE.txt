permissions044：sudo secure_path 私有验收补充

复用 SUDO-PRIVATE-HOSTNAME-FIXTURE.txt 所述同一校验工具，不复制安装、不重计附件或工具准备工作。
本补充与 Linux092 的解析修复分别针对不同故障，不把同一题/故障交叉相加。

可信容器内 root 建立仅限临时巡检工具和 /usr/bin/true 的私有白名单。
真正普通 UID1000 手动运行巡检，与实际 sudo 的完整路径/短名称请求分别对照。
可信子进程在 sudo 入口使用 ruid1000/euid0，模拟原有 sudo 入口凭据；不安装 setuid 文件。
私有 PAM permit 只排除认证混淆，命令授权仍受原白名单约束；未授权 /usr/bin/id 在变更前后都被拒。
修复只追加新可信目录到旧 secure_path，原顺序及所有目录保留；同时验证原 student/root 短命令仍可执行。
直接替换 secure_path 的负例会实际破坏旧 true 命令，不可作为修复。
目录与祖先均实际 lstat，真实 world-writable 目录会被拒，工具内容/属主/模式不变。

非 privileged 容器，cap-drop ALL 后仅 SETUID/SETGID；no-new-privileges，network=none，无宿主可写挂载。
所有 sudo/PAM/hosts 配置只在自有可丢弃容器内，进程退出后 --rm 清理；宿主默认账号/权限无变化。
没有授予 AUDIT_WRITE；sudo 的 unable to send audit message 提示真实保留，不能宣称内核审计验收。
没有验证生产 PAM、生产密码策略、任意命令或外部主机权限，不构建/拉取/提交/导出镜像。

证据：sudo-secure-path-recovery-runtime.json、permissions-secure-path-native.json、browser-permissions-secure-path。
严格审计绑定题目/执行 bundle/探针/只读工具树摘要。失败能力探针、工具准备与重跑均零题量。
