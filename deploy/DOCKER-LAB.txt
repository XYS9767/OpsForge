可选专用 Docker 实验

默认关闭。deploy/config.json 中 enable_docker_lab=false；未启用时 Dockerfile 原生题不能创建普通 Linux 工作区代替 Docker 工作区。
本地 compose.local.yaml 是 SQLite/simulation 预览，不会自动启动 Kubernetes 或 privileged DinD。

管理员准备的条件：
1. 外部 Kubernetes 实验环境、支持 NetworkPolicy 的 CNI 和专用实验节点。禁止业务节点承载 privileged DinD。
2. 现有 lab_backend=kubernetes、lab_node_selector 指向受限 Linux 工作区节点。
3. 显式设置 enable_docker_lab=true，并将 docker_node_selector 指向 Docker 专用节点标签（例如 opsforge-docker-lab=true）。
4. 构建/导入实验镜像及 docker:27-dind；Dockerfile 原生题均使用 scratch 与本地固定材料，不需要下载外部基础镜像。
5. 按原 README 部署流程执行预检和清单渲染。check-labs.py 只读核验两类节点 Ready/可调度，不打标签、不切换上下文。

显式启用后 render_deploy.py 才追加 docker-lab.optional.yaml：
- 独立 opsforge-docker namespace，单独允许 privileged Pod，不改变 opsforge-practice 的 restricted 策略。
- 原 opsforge-backend ServiceAccount 在新 namespace 仅获 Pod get/list/create/delete 和 pods/exec get/create。
- 不新增 ClusterRole，不更换默认身份，不删减原 namespace 的任何角色或权限。
- 资源配额允许旧工作区和新候选短暂并存；禁止 PVC、NodePort 和 LoadBalancer。
- 默认无入站；出站只允许 DNS 与公共 IPv4 HTTPS，拒绝内网/链路本地地址。私有镜像仓库需管理员按实际地址额外审核出站规则。

运行时：
- 普通 workspace UID1000、只读根、cap-drop ALL、no-new-privileges；只有独立 DinD sidecar privileged。
- Docker CLI 使用同 Pod tcp://127.0.0.1:2375；不挂宿主 docker.sock、hostPath、hostNetwork 或 hostPID。
- Pod 不挂载 Kubernetes ServiceAccount token。Dockerfile 题验收器仅允许受审的 scratch/本地阶段语法及固定夹具。
- 网页选择“真实 Docker 工作区”；缺少 daemon 或未启用能力时报告环境不可用，不判作学员断言错误。

关闭：
将 enable_docker_lab 改回 false 后重新部署，停止提供新 Docker 工作区。原有可选 namespace/RBAC 不自动删除；若要移除，由管理员先确认旧工作区已停止再另行执行清理。
这是资源模板和本地模拟 API 验证说明；本次没有执行外部集群部署，不能代替实际集群 NetworkPolicy、节点隔离和权限验收。
