Ceph map tools: optional, local and data-only

Pinned Debian bookworm Ceph16.2.15 packages are SHA256-checked against the official HTTPS package index. Package hooks were not read or run; no package was installed and no image was built. Package signatures were not independently verified. Tool and dependency records are in evidence/continuation/crushtool-tool-provenance.json, with every extracted file hash, the runtime version check and the finite capability probe.

Native validators use --ceph-dir ../../native-tools/ceph-16.2.15/extracted. The directory is mounted read-only. scripts/ceph-tool-launcher exposes crushtool and osdmaptool; scripts/ceph-monmap-launcher exposes monmaptool. LD_LIBRARY_PATH is scoped to each tool process. The parent process PATH and environment remain unchanged. The original lab image is used with --pull=never, nonroot UID1000, network none, read-only root and all capabilities dropped.

For a separately approved future workspace, an existing PVC may contain the extracted tree as ceph-16.2.15/ and launchers as ceph-tool-launcher and ceph-monmap-launcher. CEPH_TOOL_PVC adds one read-only volume and four read-only mounts to an ordinary workspace. It rejects invalid claims and Docker/cluster/distributed profiles. It adds no environment variable or resource/identity/namespace change. Default manifests are verified unchanged by scripts/verify_ceph_runtime_option.py. No PVC or deployment was created for this task.

These are actual offline Ceph map algorithms, not a running Ceph storage cluster. Finite CRUSH input values are not presented as live pool PGs. No MON or OSD is contacted, and no production placement rule, weight, data movement or fault recovery is claimed. Tool preparation, capability probes and repeat runs have zero conversion or fault-completion credit. Source archives do not include the separate native-tools binary directory.
