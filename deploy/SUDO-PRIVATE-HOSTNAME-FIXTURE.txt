OpsForge Linux092 私有 sudo/NSS 故障补充

用途：可信验收器在自有临时 Linux 容器复现“改名后本机名无法解析”的真实 sudo 告警。
学生题只提交 hosts 文本修复函数，仍以非 root 环境五路判分；本附件不授予学生 sudo 或 Docker 权限。

工具：Debian 官方 sudo 1.9.13p3-1+deb12u4 包的数据区；未安装包、执行维护钩子或设置 setuid 位。
官方 HTTPS Packages 索引匹配 Release 中 SHA256，包本身按索引的大小与 SHA256 核对。
原始提取 runtime 保留；runtime-with-soname 只另行物化同一包的 libsudo_util.so.0 名称。
库与工具只读挂载，原许可位于 runtime-with-soname/usr/share/doc/sudo/copyright。

运行边界：
1. 使用已有固定镜像 ID，--pull=never，不构建、拉取、提交或导出镜像。
2. 仅随机命名和标记的自有临时容器，--rm 自动清理，network=none，无宿主目录可写挂载。
3. 容器内部 /etc 可丢弃写入以演练 hosts 修复；不是宿主 /etc。工具和探针均只读挂载。
4. 不是 privileged 容器；先丢弃 ALL，只加入 SETUID/SETGID，让 sudo 自身策略读取器可临时切换内部 UID。
   保留 no-new-privileges；不加入 SYS_ADMIN、NET_ADMIN、设备或 Docker socket。
5. 调用者一直为该私有容器 root，修复前后 UID/GID/组保持；不切换宿主账号或任何默认配置。
   私有策略只列 root 本已具备的 /usr/bin/true，不给普通用户新增权限。
6. 实际检查 sudo -n -l：修复前有 unable to resolve host，参考函数只追加批准映射后告警消失。
   原策略清单、策略文件、passwd/group/nsswitch/resolv/hostname、旧别名与其他名称解析都保持。
7. 未验证普通用户 PAM 登录、任意命令授权、生产 DNS 等待时间或外部 DNS 服务恢复。

复核依据：evidence/continuation/sudo-hostname-recovery-runtime.json、
linux-sudo-hostname-native.json、browser-linux-sudo-hostname/browser-acceptance.json。

工具提取、能力探针、附件制作及重跑都计 0 题，原题与对应故障交叉不相加。
附件校验不等于完整离线恢复或最终五轮 PC 验收。
