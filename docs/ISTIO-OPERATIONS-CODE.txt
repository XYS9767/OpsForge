Istio operations programming continuation: 007–010

The source is backend/data/hands-on-continuation-istio-operations-code-native.json.
All four questions bind existing planned-new:istio:code:007–010 slots.
They are programming contracts, not deployed mesh, incident, module-review,
offline restore or PC acceptance evidence.

007 joins explicitly supplied namespace injection labels, stable revision tags
and actual pod revision evidence. It reports drift rather than modifying pods.
008 finds the exact minimum-cost optional-label projection under an observed
series budget, keeping protected dimensions and metric identity. This is a
bounded planning algorithm; it never applies scrape-time label rewrites.
009 resolves credential names in the actual gateway workload namespace, parses
real EC/RSA certificate/key material, compares SPKI public keys and checks DNS
SAN coverage. It does not verify trust, certificate lifetime or live TLS.
010 parses JSONL and request targets and applies the stated allowlist policy,
preserving duplicate approved query/header entries and correlation evidence.
It is not a general detector for arbitrary secrets in URL paths or identifiers.

Each trusted checker embeds reproducible fixtures. Certificate/key fixtures
are generated in the disposable checker process using cryptography. No private
key is persisted in this source package or added to a system trust store.
